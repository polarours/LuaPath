## 概念巩固

### Metatable 与元方法

1. **只读表代理** — `[中等]`
   实现 `readonly(t)` 返回一个代理表。读操作正常通过；写操作通过 `__newindex` 抛出错误。
   - *期望*：`local r = readonly({a=1}); print(r.a)` → `1`；`r.a = 2` → 报错
   - *提示*：为代理使用单独的 metatable，通过 upvalue 引用原始表。
   - *阶段参考*：05 — Metatable

2. **算术运算符重载** — `[中等]`
   构建一个 `Vec2` 类型，实现 `+`、`-`、`*`（标量）和 `__eq` 元方法。确保 `__tostring` 返回 `(x, y)` 格式。
   - *期望*：`Vec2.new(1,2) + Vec2.new(3,4)` → `Vec2(4, 6)`
   - *提示*：在共享的 metatable 中定义 `__add`、`__sub`、`__mul`、`__eq`、`__tostring`。
   - *阶段参考*：05 — Metatable

### 模块模式

3. **带私有状态的模块** — `[简单]`
   使用揭示模块模式（revealing-module pattern）创建一个模块。导出 `get()`、`set()`、`reset()`，但保持内部表不可访问。
   - *期望*：外部代码无法直接访问底层存储，只能通过 API 访问。
   - *提示*：在模块闭包内使用局部表。
   - *阶段参考*：06 — 模块

4. **循环依赖解决** — `[困难]`
   两个模块 `a` 和 `b` 需要互相引用。重构它们使初始化能无错完成。实现延迟初始化模式。
   - *期望*：两个模块都能成功加载；交叉引用的函数在首次调用后正常工作。
   - *提示*：返回一个包含前向引用的表；在首次使用时解析。
   - *阶段参考*：06 — 模块

### Coroutine 与调度

5. **生产者-消费者管道** — `[中等]`
   构建一个管道：一个生产者 coroutine yield 数据批次；一个消费者 coroutine 处理这些数据。使用 `coroutine.resume` 双向传递值。
   - *期望*：生产者 yield 10 个元素；消费者逐个打印；管道干净地完成。
   - *提示*：`resume(co, value)` 将数据发送到 yield 的 `coroutine.yield(...)` 调用中。
   - *阶段参考*：08 — Coroutine

6. **协作式轮转调度器** — `[困难]`
   实现一个以轮转方式运行 N 个 coroutine 的调度器。每个协程获得一个时间片（yield 计数）。超过时间片的协程被抢占并重新入队。
   - *期望*：3 个协程公平运行；输出是交错的，而非顺序的。
   - *提示*：跟踪每个协程的剩余时间片；递减后 yield。
   - *阶段参考*：08 — Coroutine

### 错误处理模式

7. **错误累积器** — `[简单]`
   编写 `pcall_accumulate(fns)`，接受一个函数列表，对每个使用 `pcall` 调用，返回 `{ok=bool, result=..., error=...}` 形式的结果。
   - *期望*：混合成功/失败的列表；没有函数会中断整个批次。
   - *提示*：使用 `pcall` 循环，将结果收集到输出表中。
   - *阶段参考*：07 — 错误处理

8. **带上下文的断言** — `[中等]`
   构建 `assertf(condition, fmt, ...)` 抛出包含调用位置的格式化错误。使用 `debug.getinfo` 获取源位置。
   - *期望*：错误消息包含失败断言的文件和行号。
   - *提示*：`debug.getinfo(2, "Sl")` 返回源文件和行号。
   - *阶段参考*：07 — 错误处理

### 迭代器与生成器

9. **滑动窗口迭代器** — `[中等]`
   实现 `window(xs, k)` 返回一个迭代器，依次 yield 列表上连续的 k 大小窗口。
   - *期望*：`window({1,2,3,4,5}, 3)` yield `{1,2,3}`、`{2,3,4}`、`{3,4,5}`。
   - *提示*：使用带索引跟踪的数值 for 循环；每次调用返回一个子表。
   - *阶段参考*：09 — 标准库

10. **有状态生成器** — `[简单]`
    构建 `make_counter(start, step)` 返回一个函数。每次调用返回下一个值。
    - *期望*：`c = make_counter(0, 2); c(); c(); c()` → `0, 2, 4`。
    - *提示*：在闭包中捕获可变的局部变量。
    - *阶段参考*：03 — 函数

### 字符串模式

11. **INI 分节解析器** — `[中等]`
    解析包含 `[section]` 标题和 `key=value` 对的字符串。返回嵌套表 `{section = {key = value}}`。
    - *期望*：`"[db]\nhost=localhost\nport=5432"` → `{db = {host="localhost", port="5432"}}`
    - *提示*：使用 `string.match` 配合 `"%[(.+)%]"` 匹配分节，`"^(%w+)%s*=%s*(.+)$"` 匹配键值对。
    - *阶段参考*：13 — 模式

### 表操作

12. **深合并** — `[中等]`
    实现 `deep_merge(base, override)` 递归合并表。`override` 中的嵌套表合并到 `base` 中，而非替换。
    - *期望*：`deep_merge({a=1, b={c=2}}, {b={d=3}})` → `{a=1, b={c=2, d=3}}`
    - *提示*：递归检查 `type(v) == "table"`。
    - *阶段参考*：04 — 表

### 函数与闭包

13. **偏应用** — `[简单]`
    实现 `partial(fn, ...)` 返回一个预绑定前导参数的新函数。
    - *期望*：`add = partial(function(a,b) return a+b end, 10); add(5)` → `15`
    - *提示*：在闭包中捕获参数；调用时追加新参数。
    - *阶段参考*：03 — 函数

## 小型项目

### 项目 1：带 TTL 的缓存系统 — `[中等]`

构建一个键值缓存，在可配置的存活时间后驱逐条目。

**需求**：`Cache.new(ttl_seconds)`、`cache:get(key)`、`cache:set(key, value)`、`cache:cleanup()`、`cache:keys()`。
**约束**：使用 `os.time()` 获取时间戳；每个条目存储 `{value=..., created=...}`；不使用外部库。
**阶段参考**：11 — 配置系统

### 项目 2：有限状态机 — `[中等]`

实现一个通用的 FSM 库。

**需求**：`FSM.new(states, initial)`、`fsm:transition(event)`、`fsm:current()`。对无效转换抛出错误。
**测试场景**：状态 `idle → loading → done | error`；事件 `start`、`finish`、`fail`、`retry`。
**阶段参考**：12 — 状态机

### 项目 3：事件系统 — `[困难]`

构建一个支持通配符的发布-订阅事件总线。

**需求**：`EventBus.new()`、`bus:on(pattern, handler)`、`bus:emit(event, ...)`、`bus:off(pattern, handler)`。末尾通配符 `*`：`"user.*"` 匹配 `"user.created"`。
**约束**：保持订阅顺序；`off` 时无 handler 泄漏。
**阶段参考**：13 — 事件系统

### 项目 4：测试框架基础 — `[困难]`

实现一个最小化的 `describe`/`it`/`assert` 测试运行器。

**需求**：`describe(name, fn)`、`it(name, fn)`、`assert.eq(a, b)`、`assert.truthy(v)`、`assert.errors(fn)`、`run_all()`。
**约束**：使用 `pcall` 隔离失败；跟踪计数；失败时打印期望值与实际值。
**阶段参考**：14 — 测试模式

## 调试任务

1. **`__index` 中的无限递归** — `[中等]`
   ```lua
   local mt = { __index = mt }
   local t = setmetatable({}, mt)
   print(t.foo)  -- 栈溢出
   ```
   - *问题*：为什么会形成循环？正确的模式是什么？

2. **Coroutine 饥饿** — `[中等]`
   一个调度器运行 3 个 coroutine，但其中一个因为从不 yield 而独占 CPU。诊断并提出修复方案。
   - *问题*：如何检测并惩罚不 yield 的 coroutine？

3. **模块重新初始化 bug** — `[困难]`
   一个模块将状态存储在局部变量中。清除 `package.loaded` 并重新 `require` 后，状态意外重置。
   - *问题*：`require` 对单次初始化提供了什么保证？

4. **共享 metatable 变异** — `[中等]`
   两个实例共享同一个 metatable。修改一个实例的 metatable 影响了另一个。找出错误并修复。
   - *问题*：逐实例 metatable vs 共享 metatable —— 什么时候用哪种？

5. **闭包循环捕获** — `[简单]`
   ```lua
   local fns = {}
   for i = 1, 5 do
     fns[i] = function() return i end
   end
   print(fns[1](), fns[3]())  -- 在 Lua 5.1 中打印 5, 5
   ```
   - *问题*：为什么 Lua 5.1 与 5.3/5.4 不同？修复方法是什么？

6. **原地排序的副作用** — `[简单]`
   `table.sort` 会修改输入表。一个排序列表的函数会静默地修改调用者的数据。
   - *问题*：如何保护调用者的数据？性能权衡是什么？

## 开放性设计问题

1. **错误哲学**：模块应该返回 `nil, err` 还是抛出 `error()`？考虑 API 人体工程学、调用者责任和可调试性。

2. **事件总线内存管理**：如何设计事件总线 API 来防止 handler 泄漏？当订阅者被垃圾回收时，什么机制会清理 handler？

3. **调度器可观测性**：哪些指标能证明 coroutine 调度器在生产环境中是健康的？如何检测饥饿、过多的上下文切换或无界队列增长？

4. **配置分层**：设计一个合并默认值、文件、环境变量和 CLI 标志的系统。每层应用什么合并语义？如何处理类型冲突？

5. **状态机可扩展性**：在 20+ 个状态和 50+ 个转换的情况下，转换表会变得难以管理。哪些结构模式能保持可维护性？考虑分层状态和表驱动设计。

6. **测试隔离**：如何确保 Lua 测试不通过全局变量或模块级局部变量共享状态？什么模式能在不需要每个测试使用独立 Lua 状态的情况下强制隔离？
